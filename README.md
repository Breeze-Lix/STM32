# ZDT_X42S 步进电机串口测试

> **本项目是一个通用的串口桥接 / 测试工程，不只用于步进电机。**
> STM32 的两路串口互相转发字节：一边接 PC（串口助手），一边接被测设备。
> 把 `main.c` 里的两个端口号换成任意两路 USART，就能用来测其他串口设备
> （传感器、蓝牙模块、另一块单片机……），详见第 6 节。
>
> 当前被测对象：ZDT **X42_V1.3** 闭环步进驱动器（Emm5.0 固件，电机 ID = **0x05**）。

---

## 1. 这个工程做什么

验证"STM32 能不能和步进驱动器正常对话"，只做最底层的字节搬运，不做协议解析：

```
PC 串口助手  ──USB-TTL──>  USART2  ──>  环形缓冲  ──>  USART1  ──>  电机
   (发命令)                                                    (收命令)

PC 串口助手  <──USB-TTL──  USART2  <──  环形缓冲  <──  USART1  <──  电机
   (看回复)                                                    (发回复)
```

特点：

- 双向字节透传，**不改写、不解析、不加换行**，发什么到电机就是什么
- 两路串口都用 **DMA + 空闲中断（IDLE）** 接收，不占用主循环轮询
- 每路一个 256 字节环形缓冲，主循环慢慢取，不会因为来不及处理而丢字节
- 串口出错（溢出/帧错误）会自动重启接收，不会"莫名其妙再也不收数据"

## 2. 硬件与参数

| 项目 | 值 |
|---|---|
| 主控 | STM32F103（F1 系列，CubeMX + HAL 库） |
| 调试口 | USART2：PA2(TX) / PA3(RX) → USB-TTL → PC |
| 设备口 | USART1：PA9(TX) / PA10(RX) → 电机通讯口 |
| 串口参数 | 115200，8 数据位，1 停止位，无校验 |
| 电机型号 | ZDT X42_V1.3（停产版，出厂默认 Emm5.0 固件） |
| 电机 ID | **0x05**（被上一任使用者改过，不是默认的 01） |
| 校验字节 | 固定 **0x6B** |
| 电机供电 | 常规版 10–29V（推荐 12 / 24V，3A 以上），与 STM32 分开供电、共 GND |

接线要点：

- 主机 **TX 接设备 RX**，主机 **RX 接设备 TX**（交叉）
- **GND 必须相连**，否则收到的全是乱码或什么都收不到
- 严禁带电插拔电机线和电源线

## 4. 用到的命令

串口助手设置：**HEX 发送、HEX 显示**，不要勾"发送新行/加回车换行"。

命令帧格式（TTL）：`地址 | 功能码 | 命令数据 | 校验码`

| 功能 | 发送 | 预期回复 | 状态 |
|---|---|---|---|
| 读固件/硬件版本 | `05 1F 6B` | `05 1F 02 82 6B` | ✅ 已实测通过 |
| 使能（锁轴） | `05 F3 AB 01 00 6B` | `05 F3 02 6B` | ⬜ 待实测 |
| 失能（松轴） | `05 F3 AB 00 00 6B` | `05 F3 02 6B` | ⬜ 待实测 |
| 速度模式（Emm） | `05 F6 01 05 DC 0A 00 6B` | `05 F6 02 6B` | ⬜ 待实测 |
| 立即停止 | `05 FE 98 00 6B` | `05 FE 02 6B` | ⬜ 待实测 |
| 读实时位置 | `05 36 6B` | `05 36 00 xx xx xx xx 6B` | ⬜ 待实测 |
| 读实时转速 | `05 35 6B` | `05 35 00 xx xx 6B` | ⬜ 待实测 |

各字段含义：

- **`05`** = 电机地址。必须等于屏幕菜单里的 `ID_Addr`，否则电机**不回复也不报错**
- **`1F / F3 / F6 / FE / 36 / 35`** = 功能码，决定"要干什么"
- **`6B`** = 固定校验字节（出厂默认，也可改成 XOR / CRC8 / Modbus）
- 速度命令里的 `05 DC` = 1500。**Emm 固件速度单位就是 RPM**（范围 0–3000），所以是 1500 RPM；
  X 固件才是 0.1RPM 单位，同一串字节含义不同，别混用
- `0A` = 加速度档位 10（范围 0–255，0 表示不用曲线加减速、直接起停）
- 回复帧第 3 字节：`02` 命令正确 / `E2` 参数越界或保护中 / `EE` 帧格式错

固件版本差异（踩过的坑）：

- 本机是 **Emm 固件**，速度模式帧长 **8 字节**
- 网上常见的 `05 F6 01 03 E8 4E 20 00 6B` 是 **X 固件**格式（9 字节），发过去只会回 `EE`
- 辨别方法：屏幕第二行显示 `0.00err` = Emm；显示实时角度且绿灯 1 秒闪 1 次 = X

## 5. 排查记录与结论

### 现象

串口助手发命令后，接收区**一个字节都没有**，电机也不动。

### 过程

1. **先怀疑链路**：确认串口助手已勾 HEX 发送、波特率 115200、TX/RX 已交叉、GND 已共地、电机 24V 已供电 —— 这几项都正常。
2. **发现误判**：早期版本代码会把收到的字节**回显**给 PC，所以"串口助手里出现我发的数据"只证明 PC↔STM32 通，**完全不能证明电机收到了**。回显是 STM32 自己打印的。
3. **缩小范围**：把 USB-TTL 从 STM32 上拔下来，直接接电机（TX→RX、RX→TX、共地），用电脑直接和电机对话。
4. **找到原因**：查看电机屏幕菜单，`ID_Addr` 是 **05** 而不是默认的 `01`。

### 结论

| 项 | 结论 |
|---|---|
| 根本原因 | 电机 ID 被改成 **05**，而命令一直用 `01` 作为地址发。地址不匹配时电机**静默丢弃，不报错**，所以表现为"完全没反应" |
| 修复方式 | 把命令首字节改成 `05`，即 `05 1F 6B` |
| 验证结果 | 收到 `05 1F 02 82 6B`，链路打通 |

### 排查经验（下次直接用）

| 现象 | 最可能原因 | 说明 |
|---|---|---|
| 一个字节都没回 | 地址不对 / 电机没供电 / 没勾 HEX 发送 / TX-RX 没交叉 / 没共地 | 地址错是最隐蔽的：电机不会报错，只会沉默 |
| 回 `EE` | 帧长度或格式不对 | 多半是 Emm / X 固件搞混，或串口助手自动加了回车换行 |
| 回 `E2` | 参数越界，或触发了低压/堵转/过流保护 | 看屏幕有无报警字样 |
| 回 `02` 但电机不转 | 只发了使能，没发运动命令；或速度为 0 | 使能只是锁轴，不是"开始转" |
| 屏幕不亮 | 供电问题 | 只插 USB-TTL 不给 24V，电机不会回任何数据 |

## 6. 复用到其他串口设备

这个工程本质是"两路串口互转"，换设备只要改端口映射。

**情况 A：还是这两路，只换设备** —— 什么都不用改，直接接线即可。

**情况 B：换成 USART3 等其它串口**

1. CubeMX 里把 USART3 配成 115200 8N1，并加上 DMA RX + 全局中断，重新生成
2. `Core/Inc/UARTRx.h` 的枚举里加一项：

   ```c
   typedef enum { UART_PORT_1 = 0, UART_PORT_2, UART_PORT_3, UART_PORT_NUM } UartPort_t;
   ```

3. `Core/Src/UARTRx.c` 的句柄表里加一项：

   ```c
   static UART_HandleTypeDef *const s_huart[UART_PORT_NUM] = { &huart1, &huart2, &huart3 };
   ```

4. `Core/Src/main.c` 主循环里把 `UART_PORT_2` / `&huart1` 换成你要用的端口

**情况 C：只想单向监听（抓设备发出的数据）** —— 删掉其中一半转发即可，例如只保留"设备 → PC"这条路。

## 8. 已知问题 / 待验证

- 读版本命令实测回复 **5 字节**（`05 1F 02 82 6B`），手册写的是 7 字节（多 2 字节硬件版本）。
  可能该固件不带硬件版本字段，也可能串口助手丢字节。**解析代码不要写死长度。**
- 表中"待实测"的命令尚未逐条跑通，跑完请把状态改成 ✅。
- 当前代码不做任何解析，位置/转速都是原始字节；单位换算（Emm 固件位置 0–65535 对应一圈，
  转速单位 RPM；X 固件为 0.1° / 0.1RPM）留到驱动层实现。
