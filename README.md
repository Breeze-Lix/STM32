# ZDT_X42S 步进电机驱动（STM32F103 + HAL + CubeMX）

> 目标：在 STM32 上用 HAL 库自己写一套 ZDT X42 步进驱动器的驱动层，
> 上层只调 `Zdt42_Enable()` / `Zdt42_SetSpeed()` 这类函数，业务代码里看不到一个十六进制字节。
>
> 当前进度：**第 2 步完成**（驱动骨架 + 一帧收发打通），下一步做回包解析与单位换算。

## 2. 硬件与参数

| 项目 | 值 |
|---|---|
| 主控 | STM32F103（F1 系列），CubeMX + HAL，Keil MDK 编译 |
| 调试口 | USART2：PA2(TX) / PA3(RX) → USB-TTL → PC 串口助手 |
| 设备口 | USART1：PA9(TX) / PA10(RX) → 电机通讯口 |
| 串口参数 | 115200，8 数据位，1 停止位，无校验 |
| 电机型号 | ZDT **X42_V1.3**（停产版） |
| 固件类型 | **Emm5.0**（屏幕第二行显示 `0.00err`、绿灯常亮） |
| 电机 ID | **0x05**（被上一任使用者改过，不是默认的 01） |
| 校验字节 | 固定 **0x6B** |
| 电机供电 | 常规版 10–29V（推荐 12 / 24V，3A 以上），与 STM32 分开供电、共 GND |

接线铁律：TX 与 RX **交叉**、GND **必须相连**、严禁带电插拔电机线。

## 3. 软件架构

三层，越往上越"说人话"：

```
应用层   main.c          只传物理量：转速、角度、使能、停止
           ↓ ↑
驱动层   zdt42.c         拼帧、加校验、解析回复  ← 十六进制只活在这一层
           ↓ ↑
收发层   UARTRx.c         DMA + 空闲中断 + 环形缓冲，只搬字节，不懂含义
         Ring.c           环形缓冲区，中断写、主循环读
```

数据流：

```
电机 ──USART1 硬件──> DMA 循环缓冲 ──IDLE 中断──> 环形缓冲 ──> Zdt42_ReadFrame() ──> 应用层
应用层 ──> Zdt42_SendFrame() ──> HAL_UART_Transmit(USART1) ──> 电机
```

为什么要这么分：

- **业务代码不碰十六进制**：换个电机只改 `zdt42.h` 里的 `ZDT42_ADDR`
- **换总线只动收发层**：以后要用 CAN 版，`zdt42.c` 的收发部分换成 CAN 帧，上层接口不变
- **中断里只搬字节**：解析和判断都放主循环，避免在中断里做耗时运算

上电后，串口助手（USART2，115200，HEX 模式）应看到：

```
=== ZDT42 self test ===
RX: 05 1F 02 82 6B
```

- `RX: ...` → 驱动层已经把"发一帧、收一帧"跑通
- `FAIL: TIMEOUT (no reply)` → 电机没回。先查供电、PA9/PA10 接线、共地

> 自测只在**上电时执行一次**。之后主循环是透传模式：串口助手敲的字节原样发给电机，
> 电机回的字节原样打印回来，方便手动试命令。

## 6. 代码说明

### 6.1 已实现的对外接口

| 接口 | 作用 |
|---|---|
| `Zdt42_Init(void)` | 初始化驱动，清空接收缓冲 |
| `Zdt42_ReadVersion(reply, max, got)` | 读固件 / 硬件版本（最短命令，用来验证链路） |
| `Zdt42_StatusStr(st)` | 把返回值翻译成可读字符串，调试打印用 |

### 6.2 内部实现要点

**`Zdt42_SendFrame(payload, len)`** —— 只负责"补头补尾"：

```
frame[0] = ZDT42_ADDR          地址
frame[1..len] = payload        功能码 + 命令数据（调用方给）
frame[len+1] = ZDT42_CHECKSUM  校验 0x6B
```

好处是以后加新命令时，只需要关心 `payload` 怎么拼，不用重复写地址和校验。

**`Zdt42_ReadFrame(buf, max, got)`** —— 收帧策略是"等到安静为止"：

1. 最多等 **200ms** 等第一个字节，等不到返回 `ZDT42_ERR_TIMEOUT`
2. 收到第一字节后继续收，连续 **15ms** 没有新字节就认为这帧结束

为什么不按手册写死长度？因为本机实测读版本只回 **5 字节**，手册写的是 7 字节。
写死长度会直接判失败，所以改成"按时间判帧尾"，兼容不同固件版本。

**`Zdt42_ReadVersion()`** —— 结构检查，注意别套错规则：

```c
长度 ≥ 4  &&  地址对  &&  功能码对  &&  末字节是 0x6B
```

读版本命令的回复**没有** `02` 状态码，第 3 字节是固件版本高字节。
而 `F3 / F6 / FD` 这些命令的回复第 3 字节才是 `02 / E2 / EE`，这个区别在第 3 步展开。

### 6.3 时间参数（都在 `zdt42.c` 顶部）

| 宏 | 值 | 含义 |
|---|---|---|
| `ZDT42_FRAME_MAX` | 32 | 一帧最大字节数（位置模式 13 字节，够用） |
| `ZDT42_TX_TIMEOUT_MS` | 50 | 发送超时 |
| `ZDT42_REPLY_TIMEOUT` | 200 | 等第一个回复字节的时间 |
| `ZDT42_GAP_MS` | 15 | 静默多少毫秒算帧尾 |

## 7. 协议速查（Emm 固件，地址 0x05）

| 功能 | 帧 | 回复 |
|---|---|---|
| 读版本 | `05 1F 6B` | `05 1F 02 82 6B` |
| 使能 | `05 F3 AB 01 00 6B` | `05 F3 02 6B` |
| 失能 | `05 F3 AB 00 00 6B` | `05 F3 02 6B` |
| 速度模式 | `05 F6 方向 速度H 速度L 加速度 同步 6B` | `05 F6 02 6B` |
| 位置模式 | `05 FD 方向 速度H 速度L 加速度 脉冲数×4 模式 同步 6B` | `05 FD 02 6B` |
| 立即停止 | `05 FE 98 00 6B` | `05 FE 02 6B` |
| 读实时位置 | `05 36 6B` | `05 36 符号 位置×4 6B` |
| 读实时转速 | `05 35 6B` | `05 35 符号 转速×2 6B` |

单位（**Emm 固件**，别和 X 固件混）：

- 速度：**RPM**，范围 0–3000
- 加速度：0–255 档位，0 = 不用曲线加减速
- 位置：位置模式用**脉冲数**，默认细分 16 → 3200 脉冲/圈；读回来的实时位置是 0–65535 对应一圈
- 回复码：`02` 正确 / `E2` 参数越界或保护 / `EE` 帧格式错

## 9. 已知问题与注意事项

1. **透传和驱动抢同一个缓冲**：主循环的透传会把 USART1 的字节全读走，所以目前只有上电自测能用驱动。
   第 3 步起要把透传移出主循环（或用宏开关只在调试时打开），否则驱动收不到回复。
2. **读版本回复 5 字节 ≠ 手册 7 字节**：缺 2 字节硬件版本。解析代码不要写死长度。
3. **只支持 Emm 固件帧格式**：X 固件的速度模式是 9 字节（0.1RPM 单位），换固件要加分支。
4. **单电机**：地址写死 0x05，多电机需改成传参。
5. 重新用 CubeMX 生成代码前，确认 `USER CODE` 区域和手写文件不会被覆盖。
